# 私人待办提醒

面向 **AstrBot + OneBot v11 QQ 私聊** 的个人待办插件。直接发送文字、通知截图或引用消息，复用 AstrBot 已配置的聊天模型识别是否包含待办、提取任务，保存到 SQLite，再按截止时间或自定义时间提醒。

**v0.3.0 默认使用 AstrBot 原生对话与工具调用，融入当前人格。** 不用先说 `/记一下`，补充时间、查询、完成和延期也不需要指令。当前人格负责和你聊天，`personal_todo` 工具负责查询和实际写入 SQLite，工具结果再交回同一个人格自然回复。插件不会替换你设置的人格或新开独立对话。

适合单人使用与小型云服务器：不在本地运行大模型，不需要 Redis、Celery 或独立数据库。定时检查使用数据库；提醒可额外生成一句人格开场，模型不可用时仍会投递基础提醒。

## 日常直接聊天

```text
你：四级词汇4作业发布了，7号晚上截止。
机器人：（沿用当前人格）具体几点截止呀？
你：晚上十一点。
机器人：（调用工具实际保存后）记好啦，7号23点截止，21点提醒你。

你：我还有什么没做？
机器人：（查询真实待办后，用当前人格回答）
你：四级作业写完了。
机器人：（将对应待办标为完成后回应）
你：另一个明天再做，晚半小时提醒我。
机器人：（若指代不唯一，先问清楚；明确后修改对应任务）
```

具体措辞由你现有的人格决定。普通闲聊、情绪倾诉继续走 AstrBot 的聊天流程，不会每条消息额外调用独立分类模型。新建或修改时间时，工具内部会进行一次结构化提取和校验。任务信息不明确时继续自然追问；多个同名任务不会自动猜测修改哪一个。

## 能做什么

- 自动识别本人私聊中的文字、图片和可读取的引用消息，一次最多提取 10 项待办。
- 标记高、普通、低三档重要性，保留判断理由与来源摘录；逾期事项单独显示标记。
- 管理待办、完成、取消、延期，覆盖指定任务的提醒安排。
- 保存任务与提醒状态，重启后恢复未发送提醒；对失败投递退避重试。
- 每日发送未完成待办汇总，可在 QQ 中开关、调整时间。
- 只处理配置的主人 QQ 的私聊待办，拒绝群聊与其他账号的待办操作。

所有时间都按北京时间（UTC+08:00）解释和显示。

## 安装与首次配置

1. 确认 AstrBot 已接好 OneBot v11，机器人可正常回复你的 QQ 私聊。
2. 在 AstrBot 的模型提供商页面配置并验证你现用的模型。插件复用该连接，无须重复填写 API Key。
3. 在 AstrBot WebUI 的插件安装入口选择从链接安装，填写 `https://github.com/ericstudio-CN/astrbot_plugin_personal_todo`。也可上传插件 ZIP，或将本目录放入 AstrBot 的 `data/plugins/astrbot_plugin_personal_todo/` 后重载。
4. 打开插件配置，填写 **`owner_qq`：你本人的 QQ 号**。未配置时插件不会启用待办操作或主动提醒。
5. `provider_id` 可留空，使用当前私聊会话的模型；也可选择/填写 AstrBot 中已配置的提供商 ID。它不是模型名称，不要把 `DeepSeek V4.1 Flash 1017` 直接当作提供商 ID。
6. **在 AstrBot 当前使用的人格 → 人格能力/工具中，允许本插件的 `personal_todo` 工具。** 如果人格已使用全部工具，无须额外选择。请使用支持工具调用的模型和 AstrBot 内置 Agent。插件不会自行绕过你的人格工具范围。
7. 用主人 QQ 私聊机器人，发送 `/待办 状态`，确认版本为 `v0.3.0`、自然对话为开启。然后直接发送通知，或问“我还有什么待办”；可用 `/待办 测试提醒` 验证主动投递。

从旧版更新：在插件卡片点击更新并重载，保留 `data/plugin_data/astrbot_plugin_personal_todo/`。缺少新配置项的旧配置默认开启自然对话，不需要重填模型密钥；已有待办和一天内的待补充草稿继续有效。更新后确认当前人格允许新工具。已通过 ZIP 安装且更新入口未识别仓库时，可以从上面的仓库链接覆盖安装同名插件；不要勾选删除持久化数据。

要求 AstrBot `>=4.5.7`，建议使用当前维护版本；未对所有旧版本进行现场验证。Python 及 AstrBot 本体依赖由现有部署提供，插件额外依赖见 `requirements.txt`。

### 模型与图片

用户现有的 DeepSeek V4.1 Flash 1017 配置可继续保留，插件不写死模型部署名。图片识别是否可用取决于**实际接入地址、该模型部署及 AstrBot 提供商是否支持图片输入**，须在现场用一张清晰截图验证。仅文字模型无法通过此插件直接识别图片；当前版本不包含独立 OCR 服务。

每次最多 3 张图片，默认每张 8 MB，支持 JPG、PNG、GIF、WebP。图片按实际字节识别格式，经限大小的下载/读取后送到现有模型连接；插件不另外保存图片副本。

## 备用 QQ 指令

日常使用可直接聊天；以下指令保留用于明确操作和排查。指令直接返回数据库明细，普通自然对话则由当前人格组织语言。

默认唤醒前缀为 `/`；如果你的 AstrBot 修改了前缀，请换成对应前缀。

| 指令 | 用法 |
| --- | --- |
| `/待办`、`/待办 列表` | 查看未完成待办 |
| `/待办 帮助` | 查看帮助 |
| `/待办 状态` | 检查版本、自然对话开关与模型提供商 |
| 直接发通知文字或图片 | 默认自动识别；普通聊天不建立任务 |
| `/待办 添加 明天18点前提交材料` | 识别并创建待办 |
| `/记一下 明天18点前提交材料，提前半小时提醒` | 添加待办的快捷方式 |
| `/记一下` + 图片 | 将指令与图片放在同一条消息中识别 |
| 引用一条通知，再发 `/记一下` | 识别引用消息中的文字和图片 |
| `/待办 今日` | 查看今天到期及已经逾期的未完成待办 |
| `/待办 详情 3` | 查看任务 3 的时间、重要性依据与提醒安排 |
| `/待办 完成 3` | 完成任务并取消其未发送提醒 |
| `/待办 取消 3` | 取消任务并取消其未发送提醒 |
| `/待办 延期 3 后天18点` | 修改截止时间，重新安排提醒 |
| `/待办 提醒 3 明天上午9点` | 覆盖该任务的提醒安排，不修改截止时间 |
| `/待办 提醒 3 半小时后` | 设置相对于当前时间的提醒 |
| `/待办 重要 3 高` | 手动改为高重要性，也支持普通、低；不改变现有提醒 |
| `/待办 补充 日期是11月8日` | 为最近一条有歧义的识别补充信息；日常可直接回答“11月8日” |
| `/待办 汇总 开`、`/待办 汇总 关` | 开关每日汇总 |
| `/待办 汇总 20:30` | 修改每日汇总时刻并开启汇总 |
| `/待办 测试提醒` | 建立一条约一分钟后发送的测试提醒，不调用模型 |

默认自然对话时，单独发送图片也可由当前人格调用工具识别。普通引用和合并转发不是同一种消息，当前版本不负责展开 QQ 合并转发记录。引用读取失败时，请重新发送原文或原图。

自然对话模式不在高优先级消息监听中抢答：人格、会话历史、工具选择、消息合并仍交给 AstrBot 正常流程。插件只向当前会话补充少量待办状态与工具使用说明；数据库结果通过原生工具调用回到同一轮对话。若关闭 `conversational_mode`，可退回 v0.2 的独立识别回执模式，此模式仍可用 `/待办 补充` 等指令。

### 时间与提醒规则

- 有精确截止时间且未指定提醒：默认提前 120 分钟提醒；高重要性任务再加一次提前一天提醒。已经过去的默认提醒点会被忽略，若全部错过且截止尚未到，则安排一次临近提醒。
- 只有截止日期、没有时刻：保留“仅日期”的精度，默认在当天 20:00 提醒；高重要性再加前一天 20:00。不把 20:00 当成用户真实的截止时刻。
- 用户明确给出提醒时间：以该提醒安排为准，不叠加默认规则。
- 无截止也无提醒时间：可建立无日期待办，不自动猜测截止或提醒；仍会进入未完成列表与每日汇总。
- 图片日期模糊、“今晚”没有具体时刻、引用里的“明天”缺少来源日期、时间已经过去等情况：先追问，**整批暂不保存**。自然对话中直接回答问题即可，也可使用备用 `/待办 补充` 指令。最近一条待补充记录可在一天内继续补充，并可跨重启恢复；草稿保存文字与已提取证据，不保存图片，图片本身看不清时请重发原图。过期通知需要改成有效日期，单纯确认过去的截止时间不会新建任务。
- 延期会取消旧的未发送提醒；没有指定新提醒时，按新的截止时间重建默认提醒。修改提醒会覆盖该任务原有的未发送提醒。

重要性是模型根据用户指定及事项后果给出的建议，不能保证完全准确。可以在添加时明确说“重要性高/普通/低”，或使用 `/待办 重要` 修改。手动修改重要性不会自动增减现有提醒，需要时再用 `/待办 提醒` 调整。模型输出会经过 JSON、字段与日期校验；不要只依赖模型对日期的理解，创建后的回执与详情应可供核对。

## 配置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `owner_qq` | 空，必填 | 你的 QQ 号，只接受该账号私聊 |
| `provider_id` | 空 | 留空复用当前会话模型，否则填写 AstrBot 提供商 ID |
| `auto_capture_enabled` | `true` | 自动识别本人私聊中的通知和待办；可关闭后使用显式指令 |
| `conversational_mode` | `true` | 通过原生聊天与工具调用融入当前人格；关闭可退回独立回执模式 |
| `persona_notifications` | `true` | 定时提醒和汇总尝试使用当前人格开场；失败仍发送基础内容 |
| `default_lead_minutes` | `120` | 精确截止时间的默认提前分钟数 |
| `date_reminder_time` | `20:00` | 只有截止日期时，当天的默认提醒时刻 |
| `daily_summary_enabled` | `true` | 每日未完成汇总开关 |
| `daily_summary_time` | `21:00` | 每日汇总时刻，`HH:MM` |
| `poll_seconds` | `30` | 定时检查间隔，10～300 秒 |
| `model_timeout_seconds` | `90` | 单次模型请求超时秒数 |
| `max_image_mb` | `8` | 每张图片大小上限 |

正常提醒误差可达一个检查间隔；云服务器停机、QQ 离线、模型或平台故障会影响识别与投递。提醒发送不依赖模型持续在线。

人格提醒优先读取该会话实际选中的人格（包括会话指定人格）；模型只生成一两句简短开场，任务编号和时间由程序原样附上，避免语气改写改变事实。人格生成最多等待 8 秒，失败或内容不合要求时使用基础提醒。生成期间任务被完成或取消，发送前会再次核对状态。

QQ 中设置的汇总开关与时间持久保存在数据库中，优先于配置页中的默认值。修改后可发送 `/待办 汇总` 查看实际生效的设置。汇总只在有未完成事项时发送，每天至多一次成功汇总；当天错过时刻后恢复运行会补发当天汇总。

## 数据、恢复与投递边界

数据保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_personal_todo/`，不放在插件代码目录。更新代码前应保留该数据目录；如需备份，先停用插件，再整体复制数据目录，避免遗漏 SQLite 的 WAL 文件。

数据库保存待办标题、时间、重要性理由、来源摘录、会话来源与提醒状态。文字和图片内容会在识别时提交给你配置的模型服务；本插件没有其他上传端点。不要把 API Key 写进待办文本或截图。

同一来源消息被重复投递时不会重复建立任务；将相同内容重新发成一条新消息仍可能产生新任务。重启后恢复未发送提醒，同一任务已错过的多个提醒点会合并为最新一点，避免逐条补发旧提醒。提醒投递失败后退避重试，最多尝试 5 次；详情中会标出多次发送失败的任务，可检查 QQ 连接后重新设置提醒。

QQ 接口成功不等于用户已阅读；在“平台已发送、程序尚未记账”时崩溃或发送超时后重试，仍可能产生重复提醒。当前版本不提供已读回执、电话/短信兜底、周期任务或跨平台同步。

## 验证

在包含插件目录的父目录运行离线测试：

```bash
python -m unittest discover -s astrbot_plugin_personal_todo/tests -v
```

离线测试覆盖保留人格与聊天历史、原生工具操作、直接回答时间补全草稿、自然查询/完成/延期的数据库操作、未授权工具检测，以及旧版独立模式回归。离线测试不能替代实际 AstrBot、DeepSeek 与 QQ 联调，也不能证明模型对每句话都能选对工具。安装后建议依次核对：

1. 主人私聊 `/待办` 可收到列表，`/待办 帮助` 可收到帮助；其他账号和群聊不触发待办操作。
2. 直接发送一条通知，检查当前人格的回复以及真实待办；缺少时间时直接回答“晚上十一点”，确认不需要指令就能继续。
3. 用一张日期明确的截图验证识别，再引用同一截图执行 `/记一下`。
4. 添加“2 分钟后提醒我喝水”，保持 QQ 在线，确认收到提醒。
5. 创建近时提醒后重启 AstrBot，确认任务仍在且能恢复提醒。
6. 直接说“这个做完了”“改到明天”“半小时后提醒我”，核对对应任务状态和旧提醒取消情况；多个候选时应追问。
7. 将汇总时刻改为几分钟后，确认私聊汇总，再恢复想要的时间。

### 日志排查

在 AstrBot 日志中搜索“个人待办”，默认 INFO 级别可看到：

- 启动：`个人待办 v0.3.0 已加载`，含自然对话开关。
- 原生模型请求：`已接入当前人格对话，personal_todo 工具可用`。
- 工具执行：`对话工具 action=add/clarify/list/complete/...`。
- 信息不明确：`需要补充信息，已保存确认草稿，待办尚未入库`。
- 真正记录成功：`已入库 count=1 ids=...`。
- 图片、模型输出或超时失败：对应 WARNING/ERROR，不会回复已保存。

例如“截止时间7号晚上”没有具体时刻时，机器人会沿用当前人格追问，你可以直接回答“晚上十一点”。自然对话模式不再输出旧版的“自动识别开始”日志。如果出现“当前会话未提供 personal_todo 工具”，检查当前人格的工具范围、插件和工具全局开关，以及是否使用 AstrBot 内置 Agent。工具不可用时插件不会偷偷添加权限。若只有口头回应却没看到工具执行/入库日志，先检查工具是否启用，再用备用 `/待办` 查询真实数据库。
